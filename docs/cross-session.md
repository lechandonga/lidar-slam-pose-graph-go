# 跨会话建图（同一场地分几次扫）

单次跑、保存后原坐标系续跑都直接可用。本文档说明第三种用法：**机器换个
位置重新开机**，新的一段里程计和时钟都从 0 开始，起点在旧图里未知，
两段有重叠，最后合成一条轨迹、一张图。

## 前提

- 旧会话必须已经 `Save` 过状态，新会话用 `LoadState` 读入。
- 新会话的起点必须落在旧图**实际覆盖过**的范围内（能看到旧会话扫过的
  墙/结构）。落在旧图之外无法定位，这是物理前提而不是参数问题。
- 两段数据各自独立：帧 ID、时间戳、里程计位姿都允许从 0 重新开始，
  流水线不再假设“接着旧轨迹末尾往下走”。
- 重叠区最好有非对称、可区分的结构；空旷/完全对称（例如一整排相同
  凹龛的走廊、空正方房间旋转 90°）可能给不出唯一解。

## 坐标、时钟、里程计如何兼容

每个会话（session）拥有各自的：

- **里程计系**：新会话首帧的轮式里程计视为 0。odom 链边只在同一会话的
  关键帧之间建立，绝不跨会话连接，因此旧会话末尾和新会话开头之间的
  “假跳变”不会污染位姿图。
- **时钟**：定位不使用绝对时间；轨迹点带 `Session` 和全流水线唯一的
  `Seq`，帧 ID/时间戳重复也不会冲突。
- **世界系**：只有一个，来自第一条轨迹。新会话通过一次全局定位求出
  “新起点在旧世界系的位姿”，之后整段都在旧世界系里跑。

## 用法

```go
p, _ := slam.LoadState("prev.gob", logger)

// 可选：给一个旧世界系下的粗略起点（位置+朝向）。
// 不给就对整张旧图做全角度搜索。
hint := &slam.LocalizeHint{Pose: roughPose, HasPose: true}

res := p.BeginSessionLocalize(firstFrame, hint)
switch res.Status {
case slam.LocalizeUnique:
    // res.Applied 是定位出的旧世界系起点位姿；首帧已锚定。
    for frames... { p.ProcessFrame(frame) }
    p.Finalize()
case slam.LocalizeAmbiguous:
    // 多个位置都像，未改动任何旧状态。可以带更准的 hint 重试。
case slam.LocalizeFailed:
    // 对不上（不在旧图范围/分数过低）。旧地图、轨迹、位姿图原封不动。
}
```

在定位成功前调用 `ProcessFrame` 会得到 `session_not_localized` 拒绝，
数据不会进入流水线。定位失败或多解时，旧状态字节级不变。

## 自动定位做了什么

1. 用旧图全部已占据单元（及关键帧表面）合成一张全局参考面。
2. 无 hint：在每个旧关键帧位置（约 2 m 去重）做全 2π 角度粗搜索；
   有 hint：只在 hint 附近的小窗口内搜索。
3. 粗评分用栅格命中重叠计数，先筛出少量空间/角度不同的候选盆地。
4. 每个候选用点-线 ICP 精配准，输出 [0,1] 对齐分数、点面残差 RMS（米）、
   信息矩阵特征值比和退化方向。
5. 聚类去重（相距小于 0.5 m / 0.35 rad 的解视为同一假设）。

判定规则（`LocalizeResult`）：

| 判定 | 条件 | 后果 |
|---|---|---|
| `unique` | 最佳分数 ≥ `LocalizeStrongScore`(0.78)，残差 RMS ≤ `LocalizeMaxRMS`(0.12 m)，且与次佳分差 ≥ `LocalizeAmbiguousMargin`(0.08) | 应用位姿，加跨会话锚边 |
| `ambiguous` | 最高分不够强，或存在两个分数接近但位置不同的假设；或平移方向退化 | **不应用**，旧状态不变，可带 hint 重试 |
| `failed` | 无任何候选达到 `LocalizeMinScore`(0.55)，或残差过大 | **不应用**，旧状态不变 |

所有尝试写入 `LocalizeDecision` 日志（`p.LocalizeDecisions()`），包含
最佳/次佳分数、残差、分差、是否使用 hint，便于人工判断。成功时还会向
位姿图加入一条连接旧关键帧的 `EdgeReloc` 锚约束（Huber 鲁棒、与 odom
链同量级的信息权重）。

## 合并时的冲突处理

- **跨会话回环**：新会话在重叠区行走时，按世界系（而非各自 odom 系）
  近邻匹配旧会话关键帧，复用既有回环的强/弱/拒绝判定；强对齐边权重与
  odom 链相当，保证两段被真正拉到一起。
- **已占据不被擦除**：`MapFreezeOccupied=true` 时，已判为占据的单元不
  会被后来的 free-space 射线清掉（不同次经过时遮挡/阴影会变）。重复扫
  过只会强化墙，不会擦空或越描越糊。
- **图压缩**：`Finalize` 和 `Save` 会先优化，再把**不同会话**中最终位
  姿重合（`CompactDistXY` 0.25 m、`CompactDistTh` 0.15 rad）的关键帧合
  并；同一会话内部不合并（保护 odom 链）。合并时重映射并去重边、删除
  自环和相互矛盾的跨链边，然后再次优化。这保证反复
  “加载→扫一点→保存→再加载”不会让关键帧/约束/地图单元一轮轮堆积。
- **地图与轨迹一致**：最后用优化+压缩后的关键帧一次性重建占据栅格，
  轨迹非关键帧按最近同会话关键帧校正；重叠区同一面墙只保留一份轮廓，
  不会出现错位双线。

## 状态文件兼容

- 当前为 **v2**。v1（单会话）文件可直接加载：新增的会话字段取安全零
  值（整段视为 session 0），关键帧缺失的 `Seq` 从轨迹恢复。
- 版本号高于当前、文件损坏或结构不一致（节点/边引用非法）会被**明确
  拒绝**并给出原因，绝不会读到一半崩溃或装出半新半旧的流水线。

## 在本地造两段有重叠的数据

见 `crosssession_test.go`。要点：

1. 用 `synth.MakeLoopPath` 造一条闭合真值路径。
2. 会话 1：`makeSession(world, loop[:cut1], seedA)`，跑完 `Finalize`。
3. 会话 2：`makeSession(world, loop[startI:], seedB)`，其中
   `startI < cut1`（起点落在会话 1 覆盖内）。每次 `synth.New` 的里程计
   和时钟都自动从 0 开始，等价于重新开机。
4. `BeginSessionLocalize(s2.frames[0], nil)` 定位，再喂入其余帧，
   `Finalize`。
5. 基准：同一条 loop 用连续帧一次跑完。比较
   - 轨迹：共同段做最优刚体 SE2 对齐后的形状 RMSE；
   - 地图：重叠区域占据单元的 precision/recall（容差若干栅格）。
