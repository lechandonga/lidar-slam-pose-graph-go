# 2D LiDAR SLAM 设计说明

本工程是一套**完全本地、确定性可复现**的二维激光 SLAM：激光与轮式里程计
均来自本地确定性合成数据（也可替换成本地回放数据），输出位姿轨迹与栅格
地图，不依赖任何外部服务、网络或系统时间随机源。

## 1. 坐标与单位约定

| 项目 | 约定 |
| --- | --- |
| 长度单位 | 米（m） |
| 角度单位 | 弧度（rad），逆时针为正，统一 `WrapAngle` 到 `(-π, π]` |
| 世界/地图系 | 右手平面系，X 向前/东，Y 向左/北，原点在地图中心 |
| 机器人本体系 | X 指向车头正前方，激光角度 0 对应正前方 |
| 位姿 `geom.Pose` | SE(2)：`(X, Y, Theta)` |
| 里程计系 | 独立坐标系，可在运行中重启（见 §5.4） |
| 栅格地图 | 固定边长正方形，分辨率默认 0.05 m/格，log-odds 占据表示 |
| 时间 | 数据自带时间戳；算法不使用墙钟时间，保证可复现 |

位姿复合约定：`Compose(a,b)` 表示先做 `b` 再做 `a`；
`Between(a,b) = a ∘ b⁻¹` 表示从 `b` 到 `a` 的相对变换。

## 2. 总体处理流程

```
激光 Scan ──有效点提取──┐
                        ├─ 扫描匹配（局部距离场 GN）
轮式 Odom ──增量预测───┘            │
                                    ▼
                     质量判定（点数/退化/残差/偏差）
                                    │
                                    ▼
                    SE(2) 切空间加权融合（含重启检测）
                                    │
                     ┌──────────────┴───────────────┐
                     ▼                               ▼
              关键帧选择（位移/转角）          非关键帧（仅轨迹）
                     │
        顺序约束加入位姿图
                     │
        回环检测 → 候选配准 → χ²/残差门限（接受/降权/拒绝）
                     │ 接受或降权
                     ▼
        位姿图 LM 优化（Huber、迭代上限、回退）
                     │
                     ▼
        用优化后关键帧位姿【整体重建】栅格地图
```

关键设计：**只有关键帧的扫描进入地图**，且回环优化后地图整体重建，因此
「地图」与「最终轨迹」在结构上不可能错位。

## 3. 扫描匹配与里程计融合

### 3.1 有效点提取

`scanmatch.ValidPoints` 丢弃：无回波（`r ≥ RangeMax`）、过近（
`r ≤ RangeMin`）、NaN。点数低于 `MinValidPoints`（默认 30）直接判为
`reject_few_points`。

### 3.2 局部距离场

- 由最近 `LocalKeyframes`（默认 8）个关键帧的观测栅格化得到局部占据图；
- 对占据格做带最近邻标签的二维欧氏距离变换（Felzenszwalb 可分离
  EDT），每个格子同时保存到最近障碍的**距离**和**最近障碍点坐标**；
- 场窗口是关键帧集合包围盒 + 感知半径的纯函数，与位姿无关，保证
  保存/续跑逐位一致；
- 局部场在新增关键帧前缓存复用，使逐帧计算量只与 `LocalKeyframes`
  相关，不随运行时间增长。

### 3.3 Gauss–Newton 配准

残差为「点到面 + 点到最近障碍点」混合：

- 点到面：距离场双线性插值距离，梯度即场梯度，在墙面方向精度高；
- 点到点：到最近障碍点距离，修正距离场在凸角处等值面外扩造成的墙角偏差。

对每点使用 Huber 降权（`MaxResidualSigma` 格），求解 3×3 增量
`(Δx, Δy, Δθ)`，带步长截断；采用**由粗到细两级**调度（距离面 ×4 的宽
收敛盆 → 全分辨率精配），改善转弯、初值略差时的收敛性。

### 3.4 异常帧判定（可区分原因）

判定码定义在 `scanmatch.Reason`：

| 判定码 | 触发条件 | 处理 |
| --- | --- | --- |
| `reject_bad_frame` | 数据源显式标记整帧损坏 | 拒绝，仅用里程计 |
| `reject_few_points` | 有效点数 < `MinValidPoints` | 拒绝，仅用里程计 |
| `reject_high_residual` | 收敛后平均残差 > `MatchMaxError`，或场内有效点 < 3 | 拒绝，仅用里程计 |
| `reject_deviation_too_large` | 配准与预测平移 > `MatchMaxPosErr` 或角度 > `MatchMaxAngErr` | 拒绝，仅用里程计 |
| `degrade_degenerate_geometry` | 信息矩阵最小特征值 < `MinInfoEigenvalue` | 接受但扫描权重 ×0.25 |
| `degrade_no_local_map` | 首帧/无局部场 | 不做扫描修正 |

任何情况下都不会静默输出错误位姿：拒绝时输出纯里程计预测位姿并在
`FrameRecord` 中留下原因；退化时降权融合并标记 `degraded_weak_scan`。

### 3.5 SE(2) 融合

在里程计预测位姿的切空间对「扫描位姿增量」与「里程计」做固定信息量加权
平均（`fusion.Fuse`）。健康扫描时关键帧直接采用扫描位姿（扫描在静态环境
中精度高于有尺度误差的轮式里程计）。

### 3.6 确定性

匹配、融合、关键帧选择均为纯算术；RNG 只用于数据生成且使用固定种子。
同一份输入重复回放，轨迹**逐帧逐位一致**（`TestDeterminism`）。

## 4. 位姿图与回环

### 4.1 节点与边

- 节点：关键帧，初值为融合位姿；节点 0 加强先验固定规范自由度；
- 顺序边（`odom`）：相邻关键帧相对位姿，信息矩阵来自 `SeqInfoXY/Th`；
- 回环边（`loop`）：带 `accepted / soft_weighted / rejected` 状态与判定
  原因、插入时 χ²，**被拒绝的边也保留在图中**以便审计。

### 4.2 回环判定规则

1. **候选筛选**：与当前位姿平移 ≤ `LoopSearchDist`，且至少相隔
   `LoopMinFrames`；
2. **航向一致性**：候选与当前航向差 ≤ `LoopMaxHeadDiff`——原地旋转产生
   的同位置但不同朝向关键帧不会被误连成回环；
3. **配准验证**：把当前关键帧扫描在旧关键帧区域做匹配，要求平均残差 ≤
   `LoopMaxError` 且偏差在 `LoopMaxPosErr/LoopMaxAngErr` 内；
4. **χ² 三级处理**（平移项按 0.5 m 尺度、角度项按门限归一）：
   - χ² ≤ `LoopSoftChi2`：`accepted`，全权重；
   - `LoopSoftChi2 < χ² < LoopRejectChi2`：`soft_weighted`，权重 ×0.25；
   - χ² ≥ `LoopRejectChi2`：`rejected`，不参与优化。

矛盾回环因此要么被识别剔除、要么稳健降权，并在边的 `Status/Reason/Chi2`
中留下**可区分的判定记录**。

### 4.3 优化器

- Levenberg–Marquardt 的 Gauss–Newton 实现，SE(2) 左扰动解析雅可比；
- 每条边 Huber 稳健核，soft 边额外 0.25 权重；
- 若一步使 χ² 上升则**回滚**位姿并增大阻尼；
- 收敛条件（满足其一）：最大位姿增量 < `OptConvergeStep`，或 χ² 相对下降
  < `OptConvergeChi2`；迭代上限 `OptMaxIter`（默认 30）；
- 纯算术、单线程、固定节点顺序，同图重复优化结果可复现。

### 4.4 有界资源

- 前端局部场只含最近 `LocalKeyframes` 个关键帧，逐帧工作量有上界；
- 地图为固定尺寸，位姿图规模随关键帧线性增长（回环/长时运行可在此基础
  上再加图稀疏化；当前以关键帧间距直接控制规模）。

## 5. 地图与状态持久化、并发

### 5.1 地图一致性

回环优化后用全部关键帧在优化位姿下**整体重建** log-odds 地图，杜绝
「轨迹已修正、地图还是旧的」错位。常规关键帧做增量栅格化（有界开销）。
射线更新时**空闲标记不会擦除已有占据证据**，避免斜掠墙角的光线侵蚀墙线。

### 5.2 状态保存/恢复

- `Pipeline.Save` 使用 gob 序列化：配置、位姿图、地图快照、关键帧、逐帧
  记录、融合状态、重启计数、局部场脏标记；
- 写入采用「临时文件 + fsync + 原子 rename」，崩溃不会留下被半更新的
  状态文件；
- `Pipeline.Load` 完整重建等价管线。由于局部场是关键帧集合的纯函数，
  续跑与一次跑完的轨迹**逐位一致**（`TestScenarioSaveAndResume`，
  差异 0）。

### 5.3 并发模型

`Pipeline` 用单一 `sync.RWMutex` 把（图、地图、关键帧、轨迹、状态）作为
一个整体保护：`Process` 持写锁，`Trajectory/Map/GraphSnapshot/Records/
LoopEdges/Bounds` 持读锁；地图自身的查询/快照也是带锁的。采集、优化与
地图查询并发时不会读到中间状态。竞态用例在 `go test -race` 下通过。

### 5.4 里程计重启

`fusion.IsRestart` 在两种情况下判定重启：

- 里程计 `Restart` 计数器变化（显式上电/复位）；
- 相邻样本平移跳变 > `RestartJump`（物理不可能的跳变）。

重启时不把跳变当作运动增量；有可信扫描则以扫描重定位，否则保持上位姿，
并在记录中标记 `odom_restart_reinitialized`，防止轨迹被拽飞。

## 6. 参数一览

所有参数集中在 `internal/slam/config.go` 的 `Config`，`DefaultConfig()`
给出与测试/演示一致的默认值。关键参数：

- 预处理：`MinValidPoints=30`、`MaxRange=20 m`、`MinRange=0.15 m`；
- 匹配：迭代上限 20、收敛步长 1e-4、残差门限 0.25 m、平移/角度偏差门限
  0.6 m / 0.35 rad、退化特征值门限 0.08、Huber 3 格；
- 融合：扫描权重 9、里程计权重 1、重启跳变 3 m；
- 关键帧：位移 0.5 m 或转角 0.35 rad，局部关键帧 8 个；
- 回环：最少相隔 25 帧、搜索半径 1.5 m、航向一致 0.8 rad、残差 0.12 m、
  soft χ²=4、reject χ²=25；
- 优化：最多 30 次、χ² 收敛 1e-4、步长收敛 1e-5、Huber δ=1；
- 地图：分辨率 0.05 m，半边长 20 m，命中/空闲 log-odds ±0.9/−0.4。

## 7. 本地构造数据、复现与验证

### 7.1 运行演示

```bash
go run ./cmd/slamdemo -out output          # 生成数据→SLAM→地图/轨迹/指标
go run ./cmd/slamdemo -v                   # 打印每帧判定
go run ./cmd/slamdemo -save-at 50          # 中途保存并加载续跑
```

输出：

- `map.pgm`：最终占据栅格地图（可直接用图片查看器打开）；
- `traj_slam.csv / traj_odom.csv / traj_truth.csv`：SLAM、纯里程计、真值
  轨迹（帧号, x, y, theta）；
- 控制台：节点/边统计、回环 accepted/soft/rejected 数量、里程计与 SLAM
  的 RMSE 与改善百分比。

默认演示（方形闭环路径，里程计带 8% 尺度漂移与噪声）结果稳定为：
里程计 RMSE ≈ 0.50 m，SLAM RMSE ≈ 0.22 m，改善约 55%。

### 7.2 合成数据

`internal/sim` 提供：

- `RectWorld`：外墙 + 内部墙段的线段世界（`Segment`）；
- `Raycast`：确定性光线求交；
- `RectTrajectory`：光滑拐角的闭环轨迹；
- `MakeScan` / `MakeOdom`：带高斯噪声、随机丢点的激光，以及带尺度误差与
  加性噪声、诚实累积漂移的里程计；种子固定即可逐位复现。

接入本地真实回放数据时，只需把数据适配成 `sensor.Scan` / `sensor.Odom`
并喂给 `Pipeline.Process`，坏帧设置 `Scan.Bad/BadReason` 即可复用全部
判定与降级逻辑。

### 7.3 测试

```bash
go test ./...                                   # 全量测试
go test -race ./internal/slam -run Concurrent   # 竞态检测（需 CGO）
go test ./internal/slam -v                      # 查看每场景输入/判定/误差日志
```

测试场景：直行、转弯、回环、噪声与坏帧、冲突/模糊回环、里程计重启、
保存后续跑、逐帧确定性、并发读写、资源有界。坏帧三类注入产生三种可区分
原因；回环修正后 RMSE 显著优于纯里程计。
